# Codori ウクレレコード記憶システム

## このファイルについて

このファイルは、Codoriを単なるかわいいキャラクターIPではなく、
ウクレレコードを覚えやすくする学習システムとして設計するための正本メモです。

Codoriのメイン用途は、ウクレレコード記憶アプリとする。
LINEスタンプは、アプリ用に作ったキャラクター画像・コードネーム画像・音声素材を使い回せる展開先として扱う。

コードをどう練習させるかの具体方針は、以下を正とする。

```text
docs/ja/learning/chord-training-policy.md
```

---

# 目的

ウクレレコードを、
フォーム暗記だけに頼らず、

```text
形 + 音 + コード名 + コード印象 + 鳥キャラクター
```

で結びつけて覚える。

初心者や理論が苦手な人でも、
「この形はこの音」「このコード名はこの鳥」という感覚で思い出せるようにする。

---

# なぜコードが覚えにくいのか

ウクレレ初心者がコードを覚えにくい理由は、主に以下。

## 1. 形だけが孤立する

コード表では、押さえる場所だけが示されることが多い。

そのため、

```text
押さえ方は見たことがある
でも名前や音の感じと結びつかない
```

状態になりやすい。

## 2. 似た形が多い

ウクレレは弦が4本で小さいため、
少し違うだけのフォームが多い。

例：

- C
- C7
- Cm
- Cadd9

は名前も似ているが、音の印象もフォームの違いも初心者には混ざりやすい。

## 3. コード名が記号に見える

`Cm`, `C7`, `Cadd9` は、慣れるまでは暗号のように見える。

意味を理解する前に、
記号、指の形、音の印象を同時に覚える必要がある。

## 4. 音の違いを言葉にしにくい

Majorとminorの違いは感じられても、
それを自分の中で分類する言葉がないと忘れやすい。

Codoriでは、ここにキャラクターとコード印象を入れる。

## 5. 練習が単調になりやすい

コード暗記は反復が必要だが、
表だけを見て覚えると飽きやすい。

キャラクター、図鑑、クイズ、音声を入れることで、
反復を少し楽しくする。

---

# Codoriでどう覚えやすくするのか

Codoriでは、コードを1つの記号として覚えるのではなく、
複数の記憶フックを作る。

| 記憶するもの | Codoriでの対応 |
|---|---|
| コード名 | `C`, `Cm`, `C7`, `Cadd9` などの表示文字 |
| コード種類 | 鳥種・体型・表情 |
| キー | 小さな色アクセント・タグ・光 |
| フォーム | キャラとは別に表示するウクレレ運指画像 |
| 音 | 短いウクレレ再生音 |
| 印象 | 明るい、静か、前に進む、広がる |
| 反復 | クイズ、図鑑、コレクション、練習履歴 |

重要なのは、どれか1つだけで覚えさせないこと。

```text
名前を見る
鳥を見る
運指画像を見る
音を聴く
押さえる
もう一度名前を見る
```

この循環で記憶を強くする。

ただし、アプリ上では「探す」と「練習する」を分ける。

```text
図鑑モード = 探す、見る、確認する
練習モード = 覚える、聞く、押さえる、流れで使う
```

`全コード`画面は図鑑モードとして扱い、
初心者の主な入口は少数コードの練習モードにする。
全120コードを一気に覚えさせる設計にはしない。

# Codoriの基本対応

Codoriの中核ルールは維持する。

```text
コード種類 = 鳥種
音名 / キー = コード名・運指画像・キー色
フォーム / 展開形 = 運指画像・ポーズ・学習状態
テンション = 小物・光・浮遊感・補助モチーフ
```

ただし、学習アプリでは以下のように使う。

# 覚えやすさ優先の推奨仕様

学習者にとって一番大事なのは、
「何が変わったから、何が変わったのか」がすぐ分かること。

Codoriでは以下を推奨仕様とする。

| 学習上の違い | 見た目の変化 | 理由 |
|---|---|---|
| コード種類が違う | 鳥種・体型・表情・基本ポーズを変える | Major、minor、7、add9を直感的に分類するため |
| 音名だけ違う | キー色、コードネーム、運指画像、小タグや光を変える | `C` と `F` を別キャラとして覚えさせないため |
| フォームだけ違う | 運指画像を変え、鳥は同じにする | 押さえ方とキャラ分類を混同しないため |
| テンションが付く | 小さな星やアクセサリを足す | 音の色づきを、複雑にしすぎず覚えるため |

例：

```text
C      → Major鳥 + C表示 + C運指 + Cキー色
F      → 同じMajor鳥 + F表示 + F運指 + Fキー色

Cm     → minor鳥 + Cm表示 + Cm運指 + Cキー色
Fm     → 同じminor鳥 + Fm表示 + Fm運指 + Fキー色

C7     → 7鳥 + C7表示 + C7運指 + Cキー色
F7     → 同じ7鳥 + F7表示 + F7運指 + Fキー色
```

鳥種、表情、基本ポーズは、音名ごとに変えない。
コードネーム文字色も、原則としてDeep Blueで統一する。

音名の違いは、
「キー色」「文字」「運指」「小さなキーアクセント」で覚える。
コード種類の違いは、
「鳥の違い」で覚える。

初期4コードの次は、新しい鳥種を増やすより先に、
既存の `Major / minor / 7` を初心者頻出コードへ展開する。

詳細な追加順は以下を正とする。

```text
docs/ja/learning/chord-key-expansion-roadmap.md
```

# ダイアトニックコードの早期導入

Codoriでは、コードを単体で覚えるだけでなく、
早い段階で「曲の中でどこへ行くか」を感じられるようにする。

最初に扱うダイアトニックは、Cメジャー周辺を基本にする。

```text
C / Dm / Em / F / G / Am
```

この6コードを、まずは「Cのまわりのよく出る仲間」として覚える。
厳密な理論名よりも、最初は以下のような感情の並びを優先する。

| コード | 使う鳥 | 感情の役割 |
|---|---|---|
| C | Major鳥 | ほっと帰る |
| Dm | minor鳥 | 少し静かに進む |
| Em | minor鳥 | そっと影が差す |
| F | Major鳥 | やわらかく広がる |
| G | Major鳥 | 前へ風が吹く |
| Am | minor鳥 | やさしく胸にしまう |

`Bdim` は、Cメジャーのダイアトニックには含まれるが、
初期では急がない。

理由：

- 初心者の最初の曲では優先度が低い
- `dim` または `m7-5` 系の新しい鳥種設計が必要になる
- 早すぎると、かわいい記憶フックより理論説明が重くなる

代わりに、`G7 -> C` を早めに扱う。

```text
G7 = Cへ帰りたくなる風
```

これにより、Codoriは単なるコード図鑑ではなく、
「音のきもちが動いて、帰ってくる」学習体験になる。

# 将来のジャズ寄りダイアトニック

基本のコード進行に慣れた後で、
ジャズ寄りの7thダイアトニックも扱う。

候補：

```text
Cmaj7 / Dm7 / Em7 / Fmaj7 / G7 / Am7 / Bm7-5
```

これは初期学習ではなく、後続フェーズにする。

理由：

- `m7`、`maj7`、`m7-5` の鳥種設計が必要になる
- いきなり入れると、初心者にはコード名が長く見える
- 先に `C / Dm / Em / F / G / Am` と `G7 -> C` の感情を覚えた方が、後で理解しやすい

Codori上の扱い：

| 種類 | 鳥の方向性 | 感情 |
|---|---|---|
| maj7 | Majorより少し大人っぽい鳥 | 透明で落ち着く |
| m7 | minorよりやわらかい鳥 | しっとり流れる |
| m7-5 | 不安定で細い鳥 | 次へ行きたがる |

ジャズ寄りダイアトニックは、
かわいさを保ちながら「少し夜っぽい」「おしゃれな小道」のような学習エリアとして追加する。

---

## コード種類

コード種類は、最も大きな記憶分類。

例：

| コード種類 | 鳥の役割 | 学習上の意味 |
|---|---|---|
| Major | 明るい基準鳥 | まず覚える基準 |
| minor | 静かな内向き鳥 | 少し影のある感情 |
| 7 | 動きのある鳥 | 次へ進みたくなる音 |
| add9 | 広がりのある鳥 | 透明感・色づけ |

学習者はまず、

```text
コード名の細かい意味より、鳥種の違い
```

を覚える。

---

## キー

キーは鳥そのものを変えず、
同じ鳥の色違いとして示す。

例：

- `C` はCタグ
- `G` はGタグ
- `F` はFタグ
- `D` はDタグ

別キャラに見えるほど全身色を大きく変えない。

理由：

- 同じMajor鳥として覚えたい
- キーごとに別キャラ化すると覚える量が増える
- アプリで同じ鳥画像を使い回しやすい

---

# ウクレレ運指画像の扱い

コード記憶アプリでは、Codoriの鳥イラストとは別に、
ウクレレ運指画像を表示する。

鳥イラストはコード種類の記憶フック。
運指画像は実際に押さえる形の記憶フック。

この2つを混ぜすぎない。

---

## 基本方針

- 鳥キャラ画像と運指画像は別アセットにする
- 同じ画面内に並べて表示する
- コードネームは両方を結びつけるラベルとして使う
- 運指画像は学習アプリ用の主情報として扱う
- LINEスタンプでは、基本的に運指画像を入れない

理由：

- キャラ画像をLINEスタンプやSNSへ使い回しやすい
- 運指画像だけ差し替えやすい
- コード種類とフォームの役割が混ざりにくい
- 初心者が「かわいい」と「押さえる場所」を別々に理解できる

---

## 弦の表示方向

Codoriアプリの運指画像では、
弦を上下方向に表示する。

暫定ルール：

```text
弦 = 上下方向
フレット = 左右方向
```

画面上では、4本の弦が上から下へ走る。
押さえる位置は、その弦上に丸印で示す。

注意：

- 一般的なコード表と違う見え方になる可能性があるため、アプリ内で向きを一貫させる
- 初回チュートリアルで「弦は上下方向」と説明する
- 左利き表示や反転表示は将来検討にする
- 運指画像の向きは、鳥キャラのポーズとは独立させる

---

## 運指画像に含める情報

初期表示：

- 4本の弦
- 必要なフレット線
- 押さえる位置の丸印
- 指番号は必要に応じて表示
- コードネーム

初期では入れすぎないもの：

- 長い理論説明
- 複雑な指番号注釈
- 複数フォームの同時表示
- 音名の大量表示

---

## 展開形 / voicing

展開形や押さえ方の違いは、別キャラにしない。

アプリでは以下で表現する。

- ポーズ違い
- 運指画像の違い
- 「かんたん」「別フォーム」などのラベル
- フォーム切り替えボタン

例：

```text
C Major bird + CフォームA
C Major bird + CフォームB
```

鳥は同じで、運指画像だけ変える。

---

## テンション

テンションはアクセサリで覚える。

例：

| 要素 | 見た目 | 学習上の役割 |
|---|---|---|
| 7 | 小さな動き・アクセント | 音が次へ行きたがる |
| add9 | 星・浮遊感 | 音が少し広がる |
| maj7 | きらめき | ふわっと大人っぽい |
| sus4 | 浮いた足・未解決感 | まだ着地しない |

ただし、アクセサリは増やしすぎない。
小サイズで読めない装飾は学習にも役立たない。

---

# 最初に覚えるコードセット

初期アプリでは、いきなり全コードを出さない。

まずは以下を推奨する。

## Step 1: C系4コード

```text
C
Cm
C7
Cadd9
```

理由：

- 同じルートでコード種類の違いを見せやすい
- Major / minor / 7 / add9 の鳥種差を確認できる
- LINEスタンプ用アセットにも展開しやすい
- 音の印象差を比較しやすい

---

## Step 2: よく使うキーへ展開

次に、同じ4種類を使ってキーを広げる。

```text
C / Cm / C7 / Cadd9
G / Gm / G7 / Gadd9
F / Fm / F7 / Fadd9
D / Dm / D7 / Dadd9
```

これはLINEスタンプ16個候補とも対応する。

---

## Step 3: よく使う基本コード

ウクレレ初級では、曲でよく出るコードを別セットとして扱う。

候補：

```text
C
F
G7
Am
Dm
Em
A7
D7
```

このセットは、実際の曲に近い。
ただし、Codoriの鳥種導入ではC系4コードを先に使う。

# Major / minor / 7 / add9 初期学習ステップ

## Lesson 1: Majorを基準にする

最初にMajor鳥を見せる。

学ぶこと：

- `C` というコード名
- C Major鳥
- Cのウクレレ運指画像
- 明るく安定した音

アプリ画面案：

```text
左：C Major鳥
右：Cの運指画像
下：再生ボタン
```

学習ゴール：

```text
Cを見ると、Major鳥と明るい基準音を思い出せる
```

---

## Lesson 2: minorで差を作る

次にminor鳥を見せる。

学ぶこと：

- `Cm` の `m` はminorの印
- Majorより静か・内向きに聞こえる
- 鳥の体型や表情もMajorと違う

比較：

```text
C  → 明るい基準
Cm → 静かな内向き
```

学習ゴール：

```text
CとCmの音・名前・鳥の違いをセットで覚える
```

---

## Lesson 3: 7で動きを覚える

次に7鳥を見せる。

学ぶこと：

- `C7` はCに動きが加わったコード
- 次のコードへ進みたくなる感じがある
- 鳥は少し前向き・動きのある姿にする

比較：

```text
C  → 安定
C7 → 動く、次へ行きたい
```

学習ゴール：

```text
7を見ると、音が少し動き出す感じを思い出せる
```

---

## Lesson 4: add9で広がりを覚える

最後にadd9鳥を見せる。

学ぶこと：

- `Cadd9` はCに広がりを足したコード
- Majorの明るさは残る
- でも少し空気が広くなる
- 星や浮遊感で覚える

比較：

```text
C     → 明るい基準
Cadd9 → 明るさ + 広がり
```

学習ゴール：

```text
add9を見ると、透明感や広がりを思い出せる
```

---

# フォーム族と移動の考え方

ウクレレコード学習では、フォームを1つずつ丸暗記するだけでは限界がある。

Codoriでは、フォームを「家族」として扱う。

## フォーム族とは

似た押さえ方をまとめたグループ。

例：

```text
同じ鳥
同じコード種類
似た指の形
違うキー
```

をまとめて覚える。

## アプリでの見せ方

フォーム族は、以下で見せる。

- 同じ鳥キャラ
- キーだけ違うタグ
- 運指画像の押さえ位置
- 横スライドで比較
- 「似ているフォーム」表示

## 移動の考え方

初心者には、いきなり理論用語で説明しない。

代わりに、

```text
同じ鳥が、別の場所に止まった
```

ように見せる。

例：

```text
C Major鳥 → Cの場所
G Major鳥 → Gの場所
F Major鳥 → Fの場所
```

鳥は同じ。
止まり木やタグが変わる。

これにより、

```text
コード種類は同じ
キーが違う
フォームが違う
```

を感覚的に整理できる。

# 感情でコード進行を覚える方法

ここでいう感情は、日常セリフではなくコードの流れの印象を指す。

コード進行は、名前の列ではなく、
小さな物語として覚える。

## 例：C - F - G7 - C

```text
C   → はじまり、安定
F   → 少し景色が変わる
G7  → 帰りたくなる
C   → 戻って安心
```

Codoriでは、

```text
安定した鳥
別の場所へ移動
動きのある7鳥
また安定した鳥へ戻る
```

として見せる。

## 例：C - Am - F - G7

```text
C   → 明るい入口
Am  → 少し内向き
F   → 景色が広がる
G7  → 次へ進む
```

このように、
コード進行を「鳥の並び」として覚える。

理論名を先に覚えなくてもよい。

# アプリ化への展開

Codoriの学習アプリでは、以下の機能へ広げられる。

## 1. コード図鑑

各コードを鳥カードとして登録する。

カード内容：

- 鳥キャラ
- コードネーム
- ウクレレ運指画像
- 再生音
- コード印象
- よく出る進行

## 2. クイズ

クイズ例：

- 音を聴いてコード名を選ぶ
- コード名を見て音を確認する
- 運指画像を見てコード名を選ぶ
- CとCmを聞き比べる

初期MVPでは、鳥キャラと再生ボタンを同時に表示し、
音・コード名・鳥キャラを結びつけるクイズを優先する。
絵だけを当てるのではなく、鳥を記憶フックにしながら音を聞き分ける。
回答後は、正解コード名と運指画像を表示して、
聞いた音を押さえる形へつなげる。

## 3. フォーム練習

アプリで、

```text
鳥 → 運指画像 → 音 → 押さえる → チェック
```

の順で練習する。

マイク判定は将来機能として検討する。

## 4. 進行ストーリー

コード進行を鳥の並びで表示する。

例：

```text
C鳥 → F鳥 → G7鳥 → C鳥
```

音を再生しながら、進行の流れを覚える。

## 5. コレクション

覚えたコードを図鑑に追加する。

ただし、コレクション要素が学習を邪魔しないようにする。

## 6. LINEスタンプへの展開

アプリで使った以下を流用する。

- 鳥キャラ画像
- コードネーム表示
- 370×320pxスタンプ構図
- 短いコード音

LINEスタンプでは日常文を入れない。
アプリと同じコードネーム表示を使う。

# 学習画面の基本構成

初期画面案：

```text
上：Codori鳥
中央：コードネーム
右または下：ウクレレ運指画像
下：再生ボタン
次：クイズへ
```

重要：

- 一画面に詰め込みすぎない
- 理論説明は開閉式にする
- 最初は音と形を優先する
- キャラは飾りではなく記憶のフックとして使う
- 運指画像はキャラとは別領域に置く
- 運指画像では弦を上下方向に表示する

---

# アプリ画面での運指表示ルール

Codoriアプリでは、運指画像をキャラクター画像と別に表示する。

推奨レイアウト：

```text
上または左：Codori鳥
中央：コードネーム
右または下：ウクレレ運指画像
下：音再生・次へ・クイズ
```

運指画像の向き：

```text
弦は上下方向
フレットは左右方向
```

初期表示で優先するもの：

- 押さえる場所がすぐ分かる
- 弦の数がすぐ分かる
- コードネームと対応している
- キャラ画像と混ざらない
- 小さいスマホ画面でも見える

避けるもの：

- 鳥キャラの体に運指図を重ねる
- コードネームより細かい数字を目立たせる
- 1画面に複数フォームを詰め込む
- 弦の向きが画面ごとに変わる

# LINEスタンプとの関係

LINEスタンプは、主目的ではなく派生先。

基本関係：

```text
アプリ用コードカード
↓
文字と音を整理
↓
LINEサイズに書き出し
↓
サウンド付きスタンプ候補
```

つまり、LINEスタンプ用にキャラを作るのではなく、
アプリ用に作った学習アセットをスタンプへ転用する。

この方針により、

- 画像制作が無駄になりにくい
- コード名と音の対応が崩れにくい
- アプリ、SNS、スタンプ、教材で同じ資産を使える

# 制作上の注意

- 理論説明を最初から重くしない
- かわいさを学習の入口にする
- ただし、コード名・フォーム・音の対応は崩さない
- 運指画像はキャラ画像とは別に管理する
- 運指画像では弦を上下方向に表示する
- 鳥キャラはコード種類を表す
- キー違いで別キャラ化しない
- フォーム違いで別キャラ化しない
- LINEスタンプ用の都合で学習構造を壊さない
