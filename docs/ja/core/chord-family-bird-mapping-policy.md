# Codori コード種類と鳥種対応ポリシー

## このファイルについて

2026-05-27時点で、このファイルに残る「コード種類=鳥種」方針は旧方針です。
本番では採用しません。

新しい正本は以下です。

```text
docs/ja/core/white-bird-action-system.md
```

このファイルは、Codoriにおける
「コード種類」と「鳥種」の対応ルールを整理する正本メモです。

目的は、学習アプリ・LINEスタンプ・SNS・グッズへ展開しても、
どこまでが固定ルールで、どこからが現フェーズの暫定デザインなのかを混同しないことです。

---

# 旧結論

以下は旧方針です。
本番方針としては撤回します。

```text
コード種類 = 鳥種
音名 / キー = コード名、運指画像、キー色
フォーム = 運指画像
テンション = 小さなアクセサリや雰囲気
```

新方針では、各コード種類に対応する具体的な鳥種を増やさず、
元の白い鳥のアクション違いと小さなワンポイントとして扱う。

つまり：

```text
本番キャラクター = 元の白い鳥
コード種類 = 白い鳥のアクション違い + 小さなワンポイント形状
キー違い = 同じアクション、同じワンポイント形状の色違い
```

---

# 固定部分

以下は、Codoriの学習体験を支える固定方針とする。

## 1. コード種類で鳥を変える

例：

```text
C      = Major鳥
Cm     = minor鳥
C7     = 7鳥
Cadd9  = add9鳥
```

コード種類が違うと、音の感情も違う。
そのため、鳥種・体型・表情・基本ポーズで記憶しやすくする。

## 2. 音名 / キーでは鳥種と表情を変えず、色を変える

例：

```text
C  = Major鳥 + C表示 + C運指 + Cキー色
F  = Major鳥 + F表示 + F運指 + Fキー色
G  = Major鳥 + G表示 + G運指 + Gキー色
```

音名ごとに鳥本体を変えると、学習者が覚える対象が増えすぎる。
そのため、鳥種・表情・基本ポーズはコード種類で固定する。

一方で、キー違いは色で表す。
色は、頬、羽先、胸元の淡い影、頭上ハネ、小タグ、小さな光などに使う。
同じコード種類の鳥だと分かる範囲で、キーごとの色違いを作る。

## 3. フォーム違いは運指画像で扱う

同じコードの別フォームや別ポジションは、新しい鳥にしない。

```text
同じコード種類 + 同じ音名
↓
鳥種、表情、基本ポーズは同じ
運指画像やフォーム表示を変える
```

## 4. 鳥は学習の分類、運指は演奏の情報

鳥は音の感情とコード種類を覚えるためのフック。
運指画像は実際の押さえ方を覚えるためのフック。

この2つを混ぜすぎない。

# 暫定部分

以下は、現フェーズでは採用しているが、将来改善してよい。

## 1. 初期4鳥の具体デザイン

現在の正式アセット：

```text
assets/approved/characters/major.png
assets/approved/characters/minor.png
assets/approved/characters/seventh.png
assets/approved/characters/add9.png
```

これらは、2026-05-22時点のアプリMVP用採用版。
学習・アプリ・LINE候補へ使ってよい。

ただし、将来の大規模リデザインや商品化前には、
小サイズ、グッズ化、他コード種類との並びを見て再評価できる。

## 2. 具体的な鳥種対応

学習効果を優先する場合、
正式展開ではコード種類ごとに鳥種差を大きくした方がよい。

理由：

- コード種類の違いがシルエットで記憶に残りやすい
- コードが増えても分類が見えやすい
- `C / F / G` のような音名違いと、`C / Cm / C7` のようなコード種類違いを混同しにくい

ただし、現行4鳥はアプリMVP用の採用版として使い続ける。
今すぐ全作り直しはしない。

正式展開時の鳥種対応候補：

| コード種類 | 表記例 | 鳥の種類 | 感情・役割 |
|---|---|---|---|
| Major | C, D, F | シマエナガ | 明るい、安心、基準 |
| minor | Cm, Dm, Am | 文鳥 | 切ない、内向き、寄り添い |
| 7 | C7, G7, A7 | カラス | いたずら、前へ進みたがる、ブルージー |
| M7 / maj7 | CM7, Cmaj7 | 白鳥 | 透明感、上品、おしゃれ |
| m7 | Cm7, Am7 | 夜雀 | 夜、余韻、エモい |
| mM7 | CmM7, Cm(maj7) | 白い鳥の不気味な笑み | サスペンス、犯人の含み笑い、過酷な運命 |
| sus4 | Csus4, Gsus4 | ペンギン | 浮遊、未解決、まだ着地しない |
| add9 | Cadd9, Dadd9 | 青い小鳥 | きらきら、青春、空気感 |
| m7-5 | Cm7-5, Bm7-5 | 白い鳥のニヒルなX傷 | 頬のバッテン傷、不安定、都会の夜 |
| dim | Cdim, Cdim7 | コキンメフクロウ | 不穏、緊迫、ミステリー |
| aug | Caug, C+ | 極楽鳥 | 夢、不思議、異世界感 |
 
この表は、正式展開時の候補として扱う。
現行MVP画像と完全一致していなくてもよい。

## 3. 将来追加する鳥種のデザイン

`m7`、`maj7`、`mM7`、`sus4`、`m7-5` は、まだ正式デザイン未作成。
追加時に、既存4鳥と並べて区別できるかを確認してから採用する。

# 現行4鳥の採用理由

| コード種類 | 採用鳥 | 採用理由 |
|---|---|---|
| Major | Major鳥 | 基準、安心、帰ってこられる感じを最も素直に表せる |
| minor | minor鳥 | Majorとの差が表情と姿勢で分かり、暗すぎない |
| 7 | 7鳥 | 次へ進みたくなる感じを、片羽と前向き姿勢で読ませられる |
| add9 | add9鳥 | 明るさに空気が足される感じを、上向き姿勢と星で覚えられる |

この4鳥は、初期学習で必要な感情差が大きい。

```text
Major = ほっとする
minor = そっとする
7 = 進みたくなる
add9 = 広がる
```

コード種類ごとの表情固定とキー色の詳細は、以下を正とする。

```text
docs/ja/characters/chord-expression-and-key-color-policy.md
```

# 将来追加候補の鳥デザイン方針

## m7

2026-05-23時点では、アプリ確認用に仮実装済み。

```text
Am7 / Dm7 / Em7
```

仮キャラクター：

```text
assets/app/characters/provisional/m7-night-sparrow.svg
```

これは正式採用画像ではない。
正式m7鳥は、別途画像生成・レビュー後に`assets/approved/characters/`へ移す。

役割：

```text
minorよりやわらかく、夜に流れる音
```

デザイン方針：

- minor鳥より少しほどけた姿勢
- しっとり、安心、やわらかい
- 悲しさを強くしすぎない
- ジャズ寄りダイアトニックの入口に向く

## maj7

役割：

```text
Majorより大人っぽく、透明に落ち着く音
```

デザイン方針：

- Major鳥より少し上品
- 透明感、夜景、静かな光
- 派手な装飾ではなく、輪郭や目線で差を出す
- add9の星感と混ざりすぎない

## mM7

役割：

```text
minorの静けさに、major 7thの張りつめた運命が乗る音
```

表記例：

```text
CmM7
Cm(maj7)
Cminmaj7
```

デザイン方針：

- ミステリーかつ過酷な運命
- 悲しみよりも、サスペンスの犯人のような含み笑い
- 黒鳥化せず、元の白い鳥の表情差分で表す
- m7の「ほどける夜」より硬く、maj7の「透明感」より影がある
- dimのミステリーよりも、ホラーではなくサスペンス感を優先する

扱い：

- 現行の主要10種類にはまだ入れない。
- `m7`と`maj7`の正式鳥を固めた後の派生候補にする。
- 全コード図鑑へ入れる場合は、主要10種類とは別の拡張セットとして検討する。

m7 / maj7 / mM7の制作前ブリーフ：

```text
docs/ja/characters/m7-maj7-mm7-production-brief.md
```

## sus4

役割：

```text
待っている、まだ戻らない音
```

デザイン方針：

- 片足を浮かせる、少し止まる、ふわっと保留する
- 7鳥ほど前へ進ませない
- 不安ではなく「まだ続きそう」
- Majorに戻る流れを学びやすい

## m7-5

役割：

```text
不安定で、次へ流れたがる音
```

デザイン方針：

- 細め、都会的、少し緊張感
- 怖くしすぎない
- dim系と統合するか分けるかは未決
- ジャズ寄りダイアトニックで重要

# 追加判断の基準

新しい鳥種を追加する前に、以下を確認する。

- 初心者が感情差を言葉にできるか
- 既存4鳥と小サイズで見分けられるか
- 1つのコード記号だけでなく、複数コードに展開できるか
- アプリで学習価値があるか
- LINEスタンプやSNSでも使い回せるか
- 理論説明が重くなりすぎないか

新しい記号があるだけでは、新しい鳥を作らない。

---

# 次の拡張判断

現時点の推奨は、以下。

```text
1. Expansion Set 01の学習体験を確認
2. A7 / D7 で既存7鳥のキー展開を進める
3. 鳥種対応表を正式化する
4. m7鳥を設計する
5. maj7鳥を設計する
6. m7-5鳥またはdim系の扱いを判断する
```

理由：

- 既存7鳥のキー展開は、新キャラなしで学習範囲を広げられる
- `A7 / D7 / G7 / C` で「7鳥は次へ進む」を強化できる
- その後に `m7 / maj7` を入れると、ジャズ寄りダイアトニックへ自然に進める

## 鳥種を正式に広げるタイミング

鳥種対応表を正式化するのは、以下のタイミングがよい。

```text
A7 / D7 の既存7鳥キー展開を確認
↓
m7 / maj7 / sus4 など新コード種類の画像制作に入る直前
```

理由：

- `A7 / D7` は既存7鳥で進められるため、今すぐ初期4鳥を作り直す必要がない
- 新コード種類に入ると、新しい鳥種差が学習設計の中心になる
- その直前に正式化すれば、画像制作とアプリ設計がぶれにくい
