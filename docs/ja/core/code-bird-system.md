# Codori コード鳥システム

## このファイルについて

このファイルは、Codoriのコードと鳥キャラクターの対応ルールを定義する正本メモ。
目的は、学習アプリ・LINEスタンプ・SNS・グッズへ広げても、
音楽理論の細かさでキャラクターIPが割れすぎないようにすること。

固定部分・暫定部分の詳しい扱いは以下も参照する。

```text
docs/ja/core/white-bird-action-system.md
```

現フェーズの判断：

```text
本番キャラクター = 元の白い鳥
コード種類 = 白い鳥のアクション違い + 小さなワンポイント形状
キー違い = 同じアクション、同じワンポイント形状の色違い
```

旧方針の「コード種類=鳥種」は撤回する。
`docs/ja/core/chord-family-bird-mapping-policy.md`は過去検討として残す。

## 優先順位

Codoriは、厳密な音楽理論の完全再現より、かわいく覚えやすいキャラクターIP設計を優先する。

このシステムで大事にすること：

- コード種類の感じを覚えやすくする
- 初心者でも使いやすい学習にする
- アプリ、LINE、SNS、グッズでキャラクターを安定させる
- 不要な差分を増やしすぎない
- 理論上の細かい違いをすべて別キャラにしない

## 中核ルール

1つのコードファミリーに、元の白い鳥の1つのアクションを対応させる。

以下の違いだけで別キャラを作らない。

- フォーム違い
- 転回形
- オクターブ位置
- ギター形
- ピアノ運指
- オープン / クローズの違い
- 音域違い
- キー移調

これらは、運指画像、レッスン、カード、アプリ状態として見せる。新しい中核キャラクターにはしない。

## キャラクター単位

Codoriの鳥は、ルート音ではなく、コードの種類やファミリーをアクションで表す。

例：

- C, F, Gは同じ安心アクションを使う
- Cm, Dm, Amは同じ寄り添いアクションを使う
- Cmaj7, Fmaj7は同じ透明にたたずむアクションを使う

ルート音は、以下で別に見せる。

- 大きなコード名
- キーごとの色
- 小さなタグ
- レッスンカード
- 小さな光やアクセント
- アプリUIの文字
- 運指画像

ルート音が変わっても、鳥種、アクション、表情、基本ポーズは変えない。
キー違いは色で表す。

## 推奨ファミリー

| コード種類 | 表記例 | 感情 | 白い鳥のアクション | 状態 |
|---|---|---|---|---|
| Major | C, Cmaj | 明るい、安心、基準 | 安心して立つ | 本番方針 |
| minor | Cm, Cmin | 静か、内向き、寄り添い | そっと寄り添う | 本番方針 |
| 7 | C7 | いたずら、前へ進む、ブルージー | 次へ誘う | 本番方針 |
| add9 | Cadd9 | きらきら、青春、空気感 | きらっと見上げる | 本番方針 |
| sus4 | Csus4, Gsus4 | 浮遊、未解決、まだ着地しない | Cと同じ丸目で空中に浮く | 本番方針 |
| m7 | Cm7, Am7, Dm7 | 夜、余韻、エモい、クール | グラサンでゆるく立つ | 本番方針 |
| maj7 | Cmaj7, Fmaj7 | 透明感、上品、おしゃれ | 透明にたたずむ | 将来候補 |

| m7-5 | Bm7-5 | 頬のバッテン傷、ニヒル、不安定 | 振り向きざまにちらっと見る | 本番方針 |

## 拡張ルール

新しいアクションを追加してよいのは、そのコードファミリーに以下がある場合。

- 初心者にもわかる独自性
- 明確な感情の役割
- シンプルなシルエット
- 繰り返し学ぶ価値
- アプリ、LINE、SNS、グッズで使う価値

記号が存在するという理由だけで鳥を増やさない。

## テンションの扱い

テンションや拡張音は、慎重に扱う。

基本方針：

- まずはadd9のように、学習上よく使うものから扱う
- 11thや13thなどは、必要になるまで小物や学習状態として扱う
- 別キャラにする場合は、感情とシルエット差が十分あることを確認する

当面はレッスン状態として扱う候補：

- 11th
- 13th
- add9
- オルタードドミナント
- セカンダリードミナント
- 分数コード

## フォーム / 展開形の扱い

フォームや展開形は、同じ鳥の状態として扱う。別キャラにはしない。

表現してよいもの：

- ポーズ違い
- 小物違い
- レッスン用の重ね表示
- 鳥の横に置く鍵盤図やフレット図
- アプリ内アニメーション状態
- SNSカルーセルでの説明

避けること：

- 第一転回形専用の新しい鳥を作る
- ドロップ2専用の新しい鳥を作る
- ギターのオープンコード形だけで新しい鳥を作る
- ピアノのシェルボイシングだけで新しい鳥を作る

## 音名 / キーの扱い

音名とキーは、鳥種や表情ではなく、色、ラベル、文脈として扱う。

使ってよい表現：

- Major鳥の近くに置く`C`タグ
- 頬、羽先、胸元の淡い影、頭上ハネのキー色
- 学習画面での小さな音名ハイライト
- 学習カードの控えめな背景アクセント
- `Fmaj7`のようなコード名表示
- ウクレレ運指画像

避けること：

- 12音それぞれのMajor鳥を作る
- キーごとに別キャラに見えるほど強く塗り替える
- ルート音ごとにシルエットを変える

## 色の扱い

色は、理論情報をすべて符号化するためではなく、
鳥の印象を少し助けるために使う。

現フェーズでは以下を優先する。

```text
鳥本体 = 白を基準
コードネーム = Deep Blue
音名 / キー = キー色、小タグ、小さな光、運指画像、コード名で表現
```

避けること：

- 音名ごとに鳥種、表情、基本ポーズを変える
- 12キーぶんの別キャラに見える鳥を作る
- コード種類の違いを色だけで表す
- キー色を強くしすぎて鳥種の違いを読みにくくする

色は補助。
主役は、鳥種・体型・表情・ポーズ・コード名・運指画像。

コード種類ごとの表情とキー色は、以下を正とする。

```text
docs/ja/characters/chord-expression-and-key-color-policy.md
```

## アクセサリの扱い

アクセサリは少なく、意味があるものだけにする。

使ってよいもの：

- 小さなスカーフ
- 小さなタグ
- 1つだけの頭ハネ
- 小さな音符チャーム
- シンプルな帽子風アクセント
- 小さな浮遊音符

避けるもの：

- 複雑な衣装
- 1キャラに複数のアクセサリ
- すべての鳥に本物の楽器ディテールを背負わせること
- スタンプサイズで消える小さな理論記号

## 学習レイヤー

同じ鳥を、学習の深さに応じて使い分ける。

### 入門レイヤー

- コード名
- 感情
- とても簡単な例
- かわいい表情

### 学習レイヤー

- コード記号
- 基本的な構成音
- 例になるルート音
- 音の説明

### アプリ / 発展レイヤー

- 鍵盤やフレット図
- 転回形やフォームの選択
- ボイシング例
- 再生
- クイズ状態

レイヤーが変わっても、鳥種、表情、基本ポーズは変えない。

## デザイン変更ポリシー

中核システムを変更する場合は、必ず理由を記録する。

将来システムを変更する場合は、以下を残す。

- 何を変えたか
- なぜ必要だったか
- どの制作物に影響するか
- 既存キャラを引き続き使うか
- 古い素材をどう扱うか

## 未決事項

- `Ninth / Extension`を1つのファミリーにするか、将来`Ninth`、`Eleventh`、`Thirteenth`へ分けるか
- dim三和音とdim7を同じ鳥にするか
- sus2とsus4を同じ鳥にするか
- sixthとminor sixthを同じ鳥にするか
- 最終的な色の扱いを、実際のスタンプサイズでどう確認するか
