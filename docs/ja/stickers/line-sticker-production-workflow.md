# Codoriスタンプ制作の考え方

Codoriは：

「コードネームを見て、音も覚えられる小鳥スタンプ」

として成立させる。

ただし、見た目は教材そのものに寄せすぎず、
かわいいキャラクターIPとして使いたくなることを優先する。

---

「このコードの小鳥として覚えたい」

と思えること。

コードネームとサウンドは主役にするが、
理論説明は入れすぎない。

# 表示内容

スタンプ内の文字はコードネームだけにする。

入れないもの：

- あいさつ
- お礼
- OK
- ごめんね
- 待機
- 応援
- 喜び
- しょんぼり
- その他の日常セリフ

表情とポーズは、日常リアクションではなくコード種の印象を補助するために使う。

# デザインルール

## 最重要

- 顔を大きく
- コード種の印象を読みやすく
- 背景を簡素に
- 小サイズ優先

---

# 表示文字ルール

## 推奨

- 短い
- コードネームを主役にする
- コードネーム以外の文字を入れない
- 音と対応させる
- 文字は太く読みやすくする
- 長い理論説明を入れない
- コードネームは背景削除後に後載せする
- 文字は独立レイヤーとして調整できる状態を保つ

---

# NG

- 長文
- 理論説明
- ネタ内輪感
- コードネーム以外の専門用語
- 日常セリフ

---

# サウンド方針

最終的にはサウンド付きスタンプを目指す。

初期方針：

- ウクレレの短いコード音
- 表示文字と同じコードを鳴らす
- スタンプ再生時に邪魔にならない短さ
- 音源は自作または権利が明確なもの

詳細は `sound-sticker-plan.md` で管理する。

---

# 色ルール

## 注意

色を増やしすぎない。

---

# 基本

コード種類ごとに、
ベースカラーを固定。

キー違いは：

- 星
- 月
- 光
- 小タグ

などで差別化。

鳥の全身色は、音名ごとに変えない。
コードネーム文字色も、原則としてDeep Blueで統一する。

理由：

- 同じコード種類を同じ鳥として覚えやすくする
- 12キー展開時に色違い量産へ進まないようにする
- LINE上でコードネームの視認性を安定させる
- 鳥種差、音名、運指の役割を混ぜない

---

# LINE審査対策

## 避ける

- 小さすぎる文字
- 背景ごちゃごちゃ
- 読めない表情
- 細かい装飾

# PNG書き出し

## 推奨

- 透過PNG
- 背景完全透明
- 太線維持

## LINEサイズ

通常スタンプの確認サイズ：

| 種類 | サイズ |
|---|---|
| メイン画像 | 240×240px |
| スタンプ画像 | 370×320px以内 |
| トークルームタブ画像 | 96×74px |

Codoriの初期パイロットでは、横長コードネームの視認性を確保するため、
スタンプ画像を最大サイズの370×320pxで確認する。

詳細は `line-export-spec.md` で管理する。

## 推奨制作順

1. 文字なしキャラ絵を作る。
2. 背景を削除し、アルファチャンネル付きPNGにする。
3. キャラの輪郭が欠けていないか確認する。
4. コードネームを後から重ねる。
5. コードネームの大きさ、色、縁取り、位置を調整する。
6. 実表示サイズで視認性を確認する。

理由：

- 文字入り画像を先に作るより、背景削除後の品質が安定する
- コードネームだけ差し替えやすい
- キー展開やサウンド付き化に対応しやすい
- `Cadd9` など長いコード名の調整を後から行える
